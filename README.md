## 1. Общ преглед на проекта

Проектът представлява напълно функционираща, автономна облачна информационна система за сигурно съхранение, управление, версиониране и споделяне на файлове. Архитектурата е проектирана по принципите на съвременните микросервиси, осигурявайки:
- **Обектно съхранение с излишък (Storage Redundancy):** Поточен паралелен запис върху 4 независими възела със защита от отказ на дисков том;
- **Стрийминг без буфериране в RAM:** Поточно качване и изтегляне с изчисление на криптографска контролна сума SHA-256 в движение;
- **Синхронизация в реално време (Realtime Sync):** Server-Sent Events (SSE) за незабавно визуално отразяване на промените във всички активни клиентски сесии;
- **Неизменяем одитен дневник (Append-Only Audit Log):** Запис на всички критични операции с роли, IP адреси и Correlation ID;
- **Наблюдаемост (Observability):** Експортиране на Prometheus метрики (`/metrics`), готово табло за Grafana и структурирани JSON логове;
- **Пълна автономност:** Работи с 0 външни npm зависимости благодарение на вградените възможности на съвременния Node.js runtime.

## 2. Предварителни изисквания (Prerequisites)

- **Node.js:** версия `v20.0.0` или по-нова (препоръчително Node.js v22 с вграден SQLite драйвер за автономно тестване);
- **Docker & Docker Compose (по избор):** за стартиране в пълна контейнеризирана среда с PostgreSQL, MinIO, Prometheus и Grafana;
- **Браузър:** Chrome, Firefox, Safari или Edge с поддръжка на ES6 и SSE.

## 3. Бърз старт (Quick Start)

### Вариант А: Автономно локално стартиране (Препоръчително за защита и демонстрация)

Системата разполага с готов скрипт за инициализация, който създава директориите за възлите, прилага миграциите и зарежда демонстрационните акаунти:

```bash
# 1. Навигиране в директорията на проекта
cd diplomenProektTU

# 2. Зареждане на демо потребители и папки
npm run seed

# 3. Стартиране на системата
npm start
```

След стартиране отворете в браузъра:
- **Уеб интерфейс (SPA):** [http://localhost:8080](http://localhost:8080)
- **Prometheus метрики:** [http://localhost:8080/metrics](http://localhost:8080/metrics)
- **Health Check проверка:** [http://localhost:8080/health/live](http://localhost:8080/health/live)

---

### Вариант Б: Контейнеризирано стартиране с Docker Compose

За разгръщане на пълния стек в изолирани контейнери:

```bash
# Стартиране на всички контейнери
docker compose up -d --build

# Проверка на състоянието и здравето (Healthchecks)
docker compose ps
```

Контейнеризирани услуги:
- **Web UI & API Gateway:** [http://localhost:8080](http://localhost:8080)
- **Grafana Дашборд:** [http://localhost:3000](http://localhost:3000) (User: `admin`, Pass: `admin_pass_2026`)
- **Prometheus конзола:** [http://localhost:9090](http://localhost:9090)
- **MinIO Конзола:** [http://localhost:9001](http://localhost:9001)

## 6. Препоръчителен сценарий за дипломна защита (Live Demo)

1. **Вход в системата:** Влезте с акаунт `student@tu-sofia.bg`.
2. **Файлови операции:** Създайте папка `Дипломна работа 2026` и качете документ чрез Drag & Drop. Наблюдавайте напредъка и появата на побитовата SHA-256 контролна сума.
3. **Демонстрация на синхронизация в реално време:** Отворете системата във втори прозорец (или инкогнито сесия). Качете нов файл от първия прозорец. Забележете как вторият прозорец получава събитието незабавно без презареждане на страницата!
4. **Споделяне:** Споделете файл с `colleague@tu-sofia.bg` с права за редакция и генерирайте публичен защитен линк с парола.
5. **Симулация на хардуерен отказ:** Влезте като `admin@tu-sofia.bg`, отворете панел **„Администрация“** и симулирайте отказ на **Storage Node #1**. Върнете се във файловия мениджър и свалете файла – системата продължава да функционира без загуба на данни!
6. **Одит и Метрики:** Прегледайте одитния дневник с точни времеви отпечатъци и Correlation ID.
